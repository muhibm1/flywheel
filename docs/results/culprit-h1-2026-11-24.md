# Bug report in, proven culprit out: held-out result

Scored once on 2026-11-24 against the rule fixed in `studies/culprit/DESIGN.md` before any held-out
case was run. Code and briefs frozen at commit `1d0688e`.

## The set

H1: 60 real regressions from 27 open-source Python projects that build agents on language models.
None of these projects was used while the tool was built. Each case gives a short, vague bug report
(no code, no identifiers, no exact error text), the version that worked, the broken version, and an
environment with the project's dependencies. The window between the two versions starts 40 to 120
changes before the true culprit. The median window was 114 first-parent changes.

## Results

| Arm | Correct | 95% interval | Comes with a proof that was run |
|---|---|---|---|
| **Flywheel: proven culprit** | **58 of 60 (96.7%)** | 88.6 to 99.1 | Yes, every answer |
| Plain model (Opus) naming the culprit by reading the history and diffs | 60 of 60 (100%) | 94.0 to 100 | No |
| Plain model (Opus) writing a probe without running it, then traced by the same tool | 37 of 60 (61.7%) | 49.0 to 72.9 | Yes, when it works |

The target was 92 percent (56 of 60). Flywheel met it.

- **False proofs: none.** Every `found` answer Flywheel gave was right. Its two misses (h1-005 and
  h1-048) ended as `invalid_probe`: no reproduction passed at the good version and failed at the
  broken one, so the tool said nothing rather than guess.
- **Cost of the search.** The tracer ran the probe at a median of 9 versions per case (at most 16).
  No model takes part in the search.
- **Agreement with the team's real fix.** At the commit where the team fixed the bug, Flywheel's
  probe passes again in 51 of 60 cases. In the other cases the probe shows a neighbouring symptom
  of the same change, or (for the two misses) there is no valid probe. This is reported apart from
  the headline, as fixed in advance.
- **Blind probes.** Of the 60 probes the plain model wrote without running anything, 30 pass at the
  good version, fail at the broken one and pass again at the fix. Tracing the 60 found the right
  culprit in 37; the other 23 never passed both end checks. None gave a wrong answer.

## What this shows

A strong model that reads the history names the right change about as often as the tool, as it did
on practice data (19 or 20 of 20). Naming alone is not where the tool earns its place. The
difference is the proof. Flywheel's answer comes with a program anyone can rerun at the culprit and
at its parent, and it never handed back a wrong answer as proven. The plain model's answer is a
claim: it has no way to tell its right answers from a wrong one, and a team acting on it still has
to reproduce the bug. When the same model tries to write that proof without running code, only 37
of 60 work. Running the reproduction and checking both ends is what lifts that to 58.

## Disclosed changes and conditions

- **One setup fix, approved before scoring.** In case h1-008 the list of source folders was written
  as one entry joined by colons instead of three entries. It was split into three before the case
  was scored. No other case was changed.
- **Fallback interpreters.** Added after the first freeze, while environments were being built and
  before any held-out case ran: a case may list a second Python, because one project's dependencies
  changed incompatibly inside its window.
- **Baseline history format.** The naming baseline read a first-parent history of the window. For
  about half the cases that history listed changed files with line counts; for the rest, after the
  line counts proved too slow to compute on the partial clones, it listed changed files only. The
  baseline could open any commit's full diff in both forms.
- **Reruns caused by the machine, not the method.** The disk filled once while baselines were
  running. Agents whose output could not be written were run again; three naming answers that had
  been reported but not saved were written down as reported. On the first parallel trace of the
  blind probes, 9 of 60 traces stopped with an error from running several traces on one repository
  at once; those 9 were traced again, one repository at a time.
- **Small rule slips.** A few baseline agents listed their case folder once before reading their
  instructions, which allowed only the diff viewer. No answer file or key was read.

## Limits

The reports are written by a model in two steps, the good and bad versions are given, the projects
are all Python agent projects, and history is first-parent only. See `studies/culprit/DESIGN.md`.
